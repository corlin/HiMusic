## P1（0.5.0）A 元数据解析与曲目表增强

1. **元数据扫描调度**：`MetadataIndex` 进入目录后渐进后台扫描，可取消；过期代次丢弃；`failedCount`/`isScanning` 语义保持。
2. **曲目表新列**：宽屏加艺术家/专辑/时长列；窄屏单行副标题拼艺术家。
3. **表头排序**：标题/艺术家/专辑/时长/大小/文件名，方向切换，排序状态可视。
4. **专辑/艺术家分区**：侧栏导航落地，聚合列表 → 点入显示该聚合的曲目（复用曲目表组件）。
5. **LRCLIB 参数**：匹配优先 metadata（title/performers/album），文件名兜底。
6. 测试：单测（排序/竞态/兜底/参数构造）+ 组件测试（表头点击、分区、窄屏）+ macOS 实机。
7. 版本号 0.5.0+1，提交并推送，更新 DEVELOPMENT.md。

## P2（0.6.0）B 播放队列与播放模式

1. **随机模式**：`setShuffleOrder` + `shuffleModeEnabled`；状态可监听；切换不中断当前曲目。
2. **播放模式 UI**：循环按钮旁加随机按钮；状态联动（循环 off/one/all + 随机开关）。
3. **队列页**：侧栏"播放列表"落地；高亮播放中、点击跳转、移除条目、空队列状态；窄屏/TV 简易列表。
4. **播放入口**：目录"播放全部/随机播放"、音乐分区"随机播放全部"。
5. **移除接口**：`PlayerController` 增加移除（处理移除当前曲目后的推进）。
6. 测试：单测（随机边界/模式切换/移除推进/空队列）+ 组件测试（队列页/按钮态）+ TV 遥控器实测。
7. 版本号 0.6.0+1，提交推送，更新 DEVELOPMENT.md。

## P3（0.7.0）C 后台播放（多端全做）

1. **原型验证**：audio_service × just_audio_media_kit 兼容性（播放/控制/通知链路），失败则回退方案。
2. **AudioHandler**：包装 play/pause/skip/seek/stop；媒体信息（artwork 兜底内置位图）。
3. **Android**：前台服务、通知渠道、TV 通知形态。
4. **iOS**：UIBackgroundModes audio、音频会话、锁屏控制、打断恢复。
5. **桌面（macOS/Windows）**：启用 audio_service，系统媒体控制可用则显示，不可用则播放器行为保持现状。
6. 测试：单测（状态映射/媒体信息）+ 真机门禁（iOS 锁屏+后台+打断、Android 手机通知、TV 桌面续播、桌面媒体控制）。
7. 版本号 0.7.0+1，提交推送，更新 DEVELOPMENT.md。

## 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| audio_service 与 media_kit 后端不兼容 | C 整体受阻 | P3 第一步原型验证，失败则评估 just_audio 原生后端或自建通知 |
| 大曲库扫描性能 | A 体验 | 渐进扫描 + 渲染不等待；曲库规模实测后调整（SPEC §7） |
| iOS 安全范围写入受限 | P0 歌词持久化 | 已识别 MethodChannel 路径，实机验证后定案 |
| 排序/筛选无统一数据模型 | A 功能蔓延 | 严格限定排序作用于当前视图，不动 queue |

## 验证方式

- 每阶段：`flutter analyze` 0 问题、完整单测全绿（现有 54 项 + 新增）、macOS debug 构建 + 运行冒烟。
- 真机门禁：iOS（corlin17mx）、Android TV（MiTV）按阶段列执行，结果记入 DEVELOPMENT.md。
- 集成测试受本环境限制无法自动执行（调试连接被拦截），改以构建 + 冒烟 + 实机人工验收替代，记录在案。
