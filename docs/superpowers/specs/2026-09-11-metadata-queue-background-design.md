# HiMusic 下一步功能设计：元数据 × 队列/播放模式 × 后台播放

日期：2026-09-11
状态：规划草案，待确认后进入实施

## 目标

在 0.4.0（三来源资料库、波形、本地/联网歌词、音量与输出设备）基础上，推进三个功能目标：

- **A. 元数据解析与曲目表增强**：曲目表展示艺术家/专辑/时长列，支持排序与分区浏览（专辑/艺术家），并反哺 LRCLIB 联网歌词匹配质量。
- **B. 播放队列与播放模式**：从"当前目录顺序播放"升级为完整队列——随机模式、队列查看与操作、从任意视图发起播放。
- **C. 后台播放**：iOS/Android 后台续播、锁屏/通知控制，Android TV 返回桌面继续播放。

三者相互独立、依赖弱，按 0.5.0 → 0.6.0 → 0.7.0 顺序推进；A 与 B 顺序可交换。

---

## A. 元数据解析与曲目表增强

### 产品范围

- 宽屏曲目表新增**艺术家、专辑、时长**三列；窄屏保持紧凑（主标题 + 单行副标题）。
- 表头点击排序：标题/艺术家/专辑/时长/大小/文件名；再次点击反向；排序状态可见。
- 侧栏"专辑""艺术家"分区从占位变为可浏览视图：聚合列表 → 点入后显示该专辑/艺术家的曲目。
- 搜索框保持现状（已匹配文件名 + 元数据字段），无需改动。
- LRCLIB 联网歌词匹配优先使用元数据（标题/表演者/专辑），文件名兜底，提升搜索结果质量。
- 元数据读取失败时曲目表回退显示文件名，不阻塞列表渲染。

### 数据模型

复用现有 `TrackMetadata`（title/album/albumArtist/performers/composers/arrangers/disc/track/duration/artwork 已齐备）与 `TrackMetadataReader`（FLAC 按需读取）。新增：

- 目录级扫描队列：`MetadataIndex` 在进入目录后**渐进后台扫描**，可取消（切目录/换源时丢弃过期结果，与歌词/波形的代次机制一致），单文件失败计入 `failedCount`（状态位已有）。
- 排序状态模型：`(字段, 升序/降序)`，作用于曲目表视图，不改变底层 `queue` 顺序。

### 组件边界

- `MetadataIndex` 扩展扫描调度，不新增 UI 逻辑。
- 曲目表排序/分区视图属于 `LibraryPage` 内新组件，不进入 `PlayerController`。
- LRCLIB 匹配参数构造收敛到 `LyricsController`，从 `TrackMetadata` 取值，缺省回退文件名。

### 性能与缓存

- 扫描按目录渐进执行，渲染不等待扫描完成（"正在读取歌曲信息…"提示已有）。
- 内存索引沿用现有 LRU 上限与淘汰策略；不新增磁盘持久化。
- 排序在已加载元数据上执行；未扫描到的条目按文件名兜底排序，扫描完成后就地更新（不重建列表）。

### 边界（不做）

- 不解析 APE/CUE（SPEC §7 中占比未知，超范围）。
- 不做艺术家图片、收藏持久化（设计验收 P3 中收藏依赖账户数据模型，另行规划）。

### 测试与验收

- 单测：排序稳定性与方向切换、扫描取消/切目录竞态、失败兜底、LRCLIB 参数构造（有/无元数据）。
- 组件测试：表头点击排序、专辑/艺术家分区视图、窄屏布局无溢出。
- macOS 实机：六首 FLAC 样本列全显示；与 LRCLIB 匹配样例对照（带标签 vs 无标签）。

## B. 播放队列与播放模式

### 产品范围

- 播放模式：顺序 / 单曲循环 / 列表循环（已有，循环按钮已接线） + **随机**（新增）。
- 侧栏"播放列表"从占位变为**当前队列页**：显示队列、播放中高亮、点击跳转、移除条目、空队列状态。
- 播放入口：目录曲目表上方增加"播放全部 / 随机播放"；音乐分区提供"随机播放全部"。
- 目录切换、换源时重置队列与播放模式（保持现状语义）。

### 数据模型与实现

- 队列：沿用 `PlayerController.queue`（当前目录音频列表），不引入新模型。
- 随机：使用 `ConcatenatingAudioSource.setShuffleOrder` + `shuffleModeEnabled`（just_audio 原生）；切换随机不中断当前曲目；播放模式状态对外可监听（供 UI 与测试）。
- 队列页操作映射到 `PlayerController` 已有能力（`playAt`、`skip`）+ 新增移除接口。

### 组件边界

- `PlayerController` 新增随机开关与移除接口，不持有 UI。
- 队列页、播放模式按钮、播放入口属于 `LibraryPage`/`NowPlayingPage` 新组件。

### 边界（不做）

- 队列跨启动持久化不做（保持"每台设备保留独立队列"的运行时语义）。
- 拖拽排序延后（先支持移除与跳转）。

### 测试与验收

- 单测：随机模式下不重复/边界行为、模式切换、移除当前曲目后的推进正确性、空队列状态。
- 组件测试：队列页跳转/移除、播放模式按钮态与切换。
- 真机：Android TV 遥控器切换模式；macOS/iOS 冒烟回归。

## C. 后台播放（audio_service）

### 产品范围

- 引入 `audio_service`，以 `AudioHandler` 包装 `PlayerController` 核心操作：播放/暂停、上一首/下一首、seek、停止。
- 通知/锁屏媒体信息：标题、艺术家、封面（`TrackMetadata.artwork`，缺省用内置封面位图）。
- Android：前台服务 + 媒体通知（播放期间运行，停止后结束）。
- iOS：`UIBackgroundModes: audio` + 音频会话配置；锁屏控制与后台续播。
- Android TV：返回桌面后音乐继续播放并保留通知控制。
- **桌面（macOS/Windows）：一并启用 audio_service**（已确认多端全做），系统媒体控制可用则显示、不可用则保持现有播放器行为。

### 风险与前置验证

- **audio_service 与 just_audio_media_kit 后端的兼容性需先原型验证**（audio_service 依赖 just_audio API，后端由 media_kit 实现，理论上兼容；验证通过后再全面接入）。
- iOS 无头模式、后台生命周期与打断恢复需真机验证。
- Android 前台服务通知渠道与 TV 通知形态需实机确认。

### 组件边界

- 新增 `AudioHandler` 适配层，映射到 `PlayerController`；`PlayerController` 不反向依赖 audio_service。
- 平台配置（Info.plist、AndroidManifest、通知渠道）与 Dart 层分离。

### 测试与验收

- 单测：handler 状态映射、媒体信息构造（有/无 artwork）。
- 真机门禁：iOS 锁屏控制 + 后台续播 + 电话打断恢复；Android 手机前台通知；TV 返回桌面续播。
- 回归：桌面行为不变。
